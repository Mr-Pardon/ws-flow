# 单结果请求：当前实现与边界

> 本页为 Server/内核阶段记录。新 Client 已接入相同任务模型，Sender.requestAll 已实现；当前状态见[架构编排与设计说明](架构编排与设计说明.md)。

2026-09-20。已实现于共享 RuntimeCore 与 Server，尚未迁入旧 WSClient，也未发布。

## 用法

```ts
import { WSServer } from '@ws-flow/server'

const server = WSServer.create({ port: 8080 })
const off = server.handleRequest<{ value: number }, number>(
  'double', ctx => ctx.data.value * 2,
)

server.onConnect(async session => {
  try {
    const status = await session.request<{ online: boolean }>(
      'device:status', {}, { timeoutMs: 5000 },
    )
    console.log(status)
  } catch (error) { console.error(error) }
})

// off() 注销公共处理器；session.handleRequest 可注册连接局部处理器。
```

远端必须实现下面的请求协议，或通过对应 Adapter 转换。旧 WSClient 的 request 仍是旧实现，不能直接用来验证本页协议。泛型只提供 TypeScript 类型提示，网络输入仍需要业务校验。

共享内核对应 `runtime.request<Result>(peer, event, input, options)` 和 `runtime.handleRequest<Input, Result>(event, handler, peer?)`。handler 获得 data、peer、event、requestId、signal；Server 额外提供 session。

`handleRequest` 是新增入口，与旧 `handle` / `route` 分离。旧 handle 的自动发送逻辑继续保留，不负责响应新请求。每个作用域同名注册会报错；Session 局部处理器优先于 Server 公共处理器。注销函数幂等，公共注册对现有与未来 Session 生效。请求处理器返回值始终是业务数据，不猜测是否为 Envelope。

## 协议边界

标准 Adapter 使用以下单结果消息：

| kind | 必需字段 | 含义 |
| --- | --- | --- |
| request | requestId、event | data 为输入 |
| response | requestId | data 为结果，可省略，代表 undefined |
| request_error | requestId、error.code、error.message | 关联失败 |
| request_cancel | requestId | 取消接收端对应入站请求 |

requestId 与普通消息 id、streamId 分开。运行时生成不透明关联 ID；它不是认证令牌。单值请求消息不得同时声明流字段；新增的 request_stream 结果类别详见《流式请求实现》。

默认错误结构不发送 stack；处理器抛出的 Error.message 会发送给调用方，业务应使用适合对外展示的错误信息。RequestError 保留 code 与 message，可从 runtime-core 或 server 导入。内置错误包括 METHOD_NOT_FOUND、HANDLER_ERROR、CAPACITY_EXCEEDED、TIMEOUT。

自定义 ProtocolAdapter 可提供 `request: { write(frame) }`，并在 read 中提取相同的内部分类与 requestId；网络结构可以完全不同。Adapter 只编码和解释，不维护待响应表、计时器或 ID。普通 write 不接管请求帧；genericAdapter 默认没有请求能力，调用 request 会明确拒绝，不自动套标准 Envelope。

标准模式新增 kind / requestId 保留字段；外部服务存在这些同名业务字段时，应使用 genericAdapter 或自定义适配器。

## 结算与调度

- 发起请求先登记，再进入发送管线，避免同步响应丢失。成功响应、错误响应、发送失败、超时、取消与断连中，第一个终态胜出。
- 超时默认 30000ms，包含排队、发送和等待结果的时间。timeoutMs: null 显式关闭超时；数值必须大于零且不超过 2147483647。
- options.signal 支持本地取消；结算时清理关联记录、计时器与监听，并阻止尚未进入 transport 的请求继续发送。
- 关联按 Peer 对象身份与 requestId 查找。两个连接的同名 ID、同一连接两个方向的同名 ID 互不干扰。
- 响应和请求不会再次进入普通订阅或旧事件路由；未知、重复、迟到响应被忽略。
- 请求 handler 与接收帧调度分离，可以等待反向 request。普通 receive middleware 仍需及时完成；旧 route / handle 的长时间处理仍占用接收调度，不应用它们替代新的请求处理器。
- 正常返回 undefined 也发送成功响应；未注册与处理器抛错返回关联错误。响应发送失败通知 useRequestErrorObserver，Server 转为 process_error。
- 中间件可以转换 data / meta，但不能修改请求的 kind、requestId、event 或 Peer。拦截已识别的请求会尝试返回错误，拦截已识别的响应会失败本地任务。响应发送管线若再次阻止错误发送，对端只能依靠超时或断连结算。
- 每个 Peer 的待响应表与入站活动请求表分别限制为 1024 条，达到上限明确拒绝；目前上限固定，未提供配置。活动重复请求 ID 不再次调用处理器。
- closePeer / dispose 拒绝待响应请求、中止入站 handler 的 signal，并禁止迟到 handler 返回结果。不能强制中断业务函数内部的任意 Promise。

## 尚未覆盖的完整任务能力

取消和超时会先结束本地等待；请求已进入 transport 且 Adapter 提供 `request.cancel.write` 时，再尽力发送 request_cancel。标准 wsFlowAdapter 已提供该能力，自定义协议需要显式声明，否则只做本地取消。尚未进入 transport 的请求不会额外发送取消帧。成功响应、普通发送失败和断连结算不会生成取消帧。

对端取消只匹配 Peer 对象身份下的入站请求，不影响同 ID 的反向待响应请求。命中时移除活动记录、以 RequestError(CANCELLED) 中止 handler.signal；迟到完成不会发送响应。重复或未知取消会被忽略，不作为普通事件分发。取消帧不传递调用方的任意异常对象或私有取消原因。

取消仍经过管线和发送调度，以保持请求在前、取消在后的传输顺序。已进入 transport 的请求无法撤回；若 transport 或中间件一直不结束，取消控制消息也可能排队等待。本地结算不依赖取消帧送达，取消发送失败经请求错误 Observer 报告。自定义调度器仍需保证相关控制帧顺序。

入站任务尚无独立执行期限，业务应自行设置可取消的超时。取消会释放内核活动记录，但不能强制停止不响应 signal 的业务函数；活动表容量并不等于底层业务并发的硬限制。已发生的副作用不会被撤销。

requestStream 已在后续阶段实现，见《流式请求实现》。多目标请求聚合、主动流远端取消、无关联 ID 的 matcher 请求或旧 Client 迁移仍未实现。已完成请求 ID 的防重放缓存也未实现，因此不保证业务恰好执行一次。自定义调度队列与底层网络缓冲的总容量仍需后续治理。

Adapter 在识别前就抛出的错误无法可靠关联到请求，只能由发送方超时收束；不要把非法输入校验等同于可恢复的响应匹配。
